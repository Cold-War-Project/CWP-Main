# 05_scripted_triggers_values - scripted_triggers, script_values, customizable_localization, scripted_tests

Logs scanned: error.log, error.1.log, error.2.log (error.3.log has no entries in this scope). About 700 unique error lines were collapsed into the patch files below.

## Method
- Every patch file is `common/<folder>/zz_cwp_fix_<vanilla file name>`; it contains only the top-level blocks that contain an error line. Each block is a line-for-line copy of the vanilla block (generated by script, not retyped) with `REPLACE:` prefixed to the key and only the invalid references edited.
- Edits: key mapped to the CWP equivalent per `00_mapping.md` where one exists; otherwise the single statement is replaced with `always = no` (inside OR it simply drops out; inside NOT/NOR it becomes true, which is correct for a thing that cannot exist). A mapped line that became an exact duplicate of a sibling line in the same list was dropped.
- Where the log pointed at an enclosing `AND = {`/`}` line instead of the statement (00_ai_triggers, 00_coa_triggers, 00_ip4, 00_victoria), the offending key was located inside the reported sub-block (or, failing that, the top-level block) and fixed there.
- All files validated for balanced braces by script; every output block starts with `REPLACE:`; no mapped vanilla key remains in any patched block except inside localization_key names or comments.
- `Invalid right side during comparison 'g'` (00_victoria_scripted_triggers goods_is_* and 99_fr_custom_loc) is the follow-on error of `g:<missing good>`; fixed by the goods mapping/removal.

## Decisions / deviations from 00_mapping.md
- Princely-state governments (`is_princely_state`): the 18 gov_princely_state_* / gov_regency_princely_state_* lines became `always = no` instead of gov_colonial_administration_fallback. The trigger's trailing AND branch (Indian region, Hindu/Sunni/Shia, subject of a colonial power, now using HND instead of BHT) already identifies princely states; the fallback government would add false positives. Add a `has_government_type = gov_colonial_administration_fallback` line if you want the mapping literally. (judgment)
- customizable_localization ip4_custom_loc.txt: regency title entries for missing governments use `always = no` (not gov_regency_kingdom): the first match wins, so mapping would show titles such as Ras or Maharani for ordinary kingdoms. The CWP governments gov_regency_kingdom and gov_regency_kingdom_constitutional keep their entries (never in error).
- customizable_localization 99_fr_custom_loc.txt (goods names): both removed and mapped goods use `always = no` (not mapped to CWP goods), because the entry would otherwise output the old good's loc key (for example 'fertilizer' for chemicals). The CWP goods fall through to the template's other entries.
- AI army/navy size multipliers (ai_script_values wanted_army_size, wanted_navy_size) stack by multiplication, so mapping several old techs to one CWP tech would apply the factor repeatedly. Graduated targets were used instead of the mapping table: ironclad_tech->naval_warfare, dreadnought_tech->screening_vessels, battleship_tech->naval_aviation, general_staff->divisional_organization, trench_works->industrial_warfare, nco_training->squad_specialist_weapons, mobile_armor->armored_warfare. (judgment)
- tools/scripted_tests/ip3.txt: dev-only test script whose top-level key is `tests` with nested named tests, so REPLACE cannot target a single test. Full-file overwrite with the two government lines changed to `always = no` (comment added). Not needed for gameplay; skip the override if you do not run scripted tests (the 2 errors are dev-tool only).
- Mapping that collapses several keys into one (cultures, ideologies, countries) produced duplicate lines; duplicates in the same list were dropped (counted in the table).
- customizable_localization blocks use `REPLACE:`; the custom-loc database is a keyed database so this should work, but I found no in-game precedent for it. If REPLACE: is rejected there, the fallback is a same-name full override of those 11 files.
